# SAT Practice — Premium Update

Это доработка существующего сайта с сохранением его тёмного дизайна и интерфейса официального тренажёра. Публикация на прежнем адресе автоматически не выполнялась: нужно обновить репозиторий и развернуть сервер.

## Что изменено

- Раздел авторских вариантов и его банк из 1470 заданий удалены. Также удалён отдельный генератор из 120 самостоятельно составленных вопросов. Старые публичные `app.js`, `engine.js`, `static-api.js` больше не используются и не входят в сборку.
- На месте ссылки «Авторские тренировочные варианты» — **+998 95 570 55 66**. Номер кликабельный: `tel:+998955705566`.
- Сохранены 10 подборок из внешнего банка College Board, по 98 заданий в попытке, четыре модуля, перерыв, калькулятор, отметки, исключение ответов, мобильное разделение текста и вопроса. Это независимые подборки, а не официальные нумерованные тесты Bluebook. Адаптация и оценка балла — приблизительные учебные модели.
- Один полный тест и его разбор доступны бесплатно. Остальные варианты открываются с Premium. Первый тест доступен гостю без регистрации; гостевой прогресс привязан к этому браузеру. Для прогресса между устройствами проходите тест после входа в аккаунт. Автоматический перенос гостевой попытки при регистрации пока не реализован.
- Бесплатны два урока: линейные уравнения и transitions, с практикой. Premium открывает все шесть опубликованных уроков, персональный план, анализ слабых тем, расписание повторений 1/3/7/14 и график прогресса. Не заявляется наличие полного курса по всем темам SAT.
- Практика после урока использует задания того же внешнего банка. Правильные ответы и исходные объяснения остаются на английском. Сами уроки, правила и примеры подготовлены на RU / UZ (латиница) / EN. Полный перевод каждого внешнего задания и каждого его объяснения не добавлен и не обещается на странице тарифа.
- Полные тесты проверяются сервером. Ключи и объяснения не выдаются до завершения теста. Результаты создают проверяемые события для статистики и повторений. Есть самооценка причины ошибки и сохранение сообщений об ошибках.
- **Premium — 19 000 сумов / 30 дней**, без автоматического списания. Цена меняется через `PREMIUM_PRICE_UZS` на сервере.
- Страница тарифа, заказы, история, статус подписки, продление и серверная проверка срока. Никакого `premium=true` в localStorage.
- MongoDB Atlas поддерживается через `MONGODB_URI`. SQLite остаётся вариантом для локального запуска.

## Запуск на Windows

Нужен Node.js 24. Откройте папку, где находится `package.json`:

```powershell
npm ci
Copy-Item .env.example .env
npm start
```

Затем откройте `http://localhost:3000`. Можно использовать `start-windows.bat`. Для Linux/macOS вместо `Copy-Item` выполните `cp .env.example .env`.

Без `MONGODB_URI` данные сохраняются в `data/sat.sqlite`. При перезапуске локального приложения они сохраняются. Не публикуйте `.env`, базу данных и содержимое `data/`.

## Самый простой запуск на Render + MongoDB

1. Загрузите **содержимое этой папки** в репозиторий: `package.json`, `package-lock.json`, `server/`, `public/`, `scripts/` и прочие файлы. `node_modules`, `.env` и `data/` не загружайте.
2. В MongoDB Atlas создайте базу/пользователя для приложения и разрешите подключение с исходящих адресов вашего сервиса Render. Скопируйте строку подключения в приватные переменные Render.
3. Render → New → Web Service → нужный репозиторий. Root Directory оставьте пустым, если `package.json` лежит в корне. Runtime: Node. Build Command: `npm ci --omit=dev`. Start Command: `npm start`. Health Check: `/api/health`. Node: 24.
4. Задайте Environment:

```dotenv
NODE_ENV=production
MONGODB_URI=ВАША_ПРИВАТНАЯ_СТРОКА_MONGODB
MONGODB_DB=sat_preparation
PUBLIC_ORIGIN=https://ВАШ-СЕРВИС.onrender.com
ALLOWED_ORIGINS=https://ВАШ-СЕРВИС.onrender.com
FRONTEND_URL=https://ВАШ-СЕРВИС.onrender.com/
PAYMENT_MODE=manual
PREMIUM_PRICE_UZS=19000
```

Используйте настоящий адрес Render. `PORT` Render устанавливает сам. При использовании MongoDB постоянный диск для SQLite не нужен. На платном постоянно работающем сервисе нет задержки запуска после простоя. При выборе бесплатного тарифа учтите его ограничения.

Файл `render.yaml` — необязательная заготовка Blueprint с платным планом `starter`; не применяйте его, если хотите сначала бесплатный запуск. Он не содержит секретов.

5. Проверьте `/api/health`: ожидается `ok: true` и `database: "mongodb"`. Затем проверьте регистрацию, бесплатный тест, тариф и создание заказа. Подключение к вашей реальной Atlas-базе из этой сборки не проверялось: ваша строка подключения не предоставлялась.

Внешний банк вопросов должен быть доступен именно с развёрнутого сервера. Его доступность не контролируется этой платформой. Если банк не отвечает, показывается сообщение об ошибке и кнопка повторной загрузки; выдуманные вопросы вместо него не подставляются.

## Оплата без реквизитов платёжной системы

По умолчанию включён **ручной режим**, а не автоматическое получение денег:

1. Ученик входит в аккаунт → Premium → «Открыть Premium».
2. Сервер создаёт заказ на 19 000 сумов. На странице показаны номер заказа и ваш телефон.
3. Вы отдельно договариваетесь о способе оплаты и **проверяете фактическое поступление**.
4. В терминале владельца сервера с доступом к той же MongoDB выполните:

```bash
npm run admin -- orders
npm run admin -- approve НОМЕР_ЗАКАЗА
```

Команду также можно выполнять локально из этой папки с вашим `.env`, содержащим `MONGODB_URI` той же базы. Ученику достаточно нажать «Проверить статус». Повторный запуск `approve` не добавляет вторые 30 дней. У покупателя нет API для ручного открытия подписки. Скриншот перевода или слова ученика сами по себе не активируют доступ.

Для просмотра сообщений об ошибках:

```bash
npm run admin -- reports
```

## Автоматическая оплата Payme

Подготовлен обработчик Merchant API и серверная активация, но **ваша настоящая касса ещё не подключена**. Нужны договор/касса Payme Business и выданные провайдером merchant ID и ключ. Комиссии и требования подключения уточняются у Payme. Click в эту сборку не добавлен.

Настройки сервера:

```dotenv
PAYMENT_MODE=payme
PAYME_MERCHANT_ID=ВАШ_ID_КАССЫ
PAYME_KEY=ВАШ_СЕКРЕТНЫЙ_КЛЮЧ
FRONTEND_URL=https://ВАШ-САЙТ/
```

В кассе задаётся аккаунт `order_id` и HTTPS Merchant API Endpoint:

```text
https://ВАШ-СЕРВЕР/api/payments/payme
```

Реализованы `CheckPerformTransaction`, `CreateTransaction`, `PerformTransaction`, `CancelTransaction`, `CheckTransaction`, `GetStatement`, проверка Basic Authorization, суммы в тийинах, таймаут незавершённой транзакции 12 часов, уникальность ID транзакции, повторные уведомления и отмена доступа по отменённой покупке. Возврат со страницы Payme не считается подтверждением оплаты. Доступ включается только по подтверждённой операции провайдера.

Перед приёмом реальных денег пройдите тестирование и настройку кассы с Payme. Проверки этой сборки используют локальные имитации callback-запросов; реальная оплата, песочница кассы и фискальные требования вашего бизнеса не проверялись. Секреты вводятся только в Environment сервера, никогда в `public/config.js` или репозиторий.

Документация протокола: https://developer.help.paycom.uz/metody-merchant-api/

## Тестовый режим без списания

Для локальной демонстрации:

```dotenv
NODE_ENV=development

```

В заказе появятся явно подписанные тестовые кнопки успеха и отмены. Они не списывают деньги. С `NODE_ENV=production` сервер отказывается запускать `demo`. В обычных режимах маршрут демо-оплаты не работает.

## Если хотите оставить фронтенд на GitHub Pages

Сначала запустите сервер на Render. Затем в этой папке:

```powershell
$env:API_URL="https://ВАШ-СЕРВИС.onrender.com/api"
npm run pages
```

В репозиторий GitHub Pages загрузите **только содержимое `dist/github-pages/`**. На Render добавьте точный origin фронтенда, например:

```dotenv
ALLOWED_ORIGINS=https://saidkhujalucky-hub.github.io
FRONTEND_URL=https://saidkhujalucky-hub.github.io/-SAT/
PUBLIC_ORIGIN=https://ВАШ-СЕРВИС.onrender.com
```

Путь в `FRONTEND_URL` должен совпадать с реальным репозиторием: на вашем скриншоте это `/-SAT/`; если используете `/SAT.4/`, укажите его. У `PUBLIC_ORIGIN` и `ALLOWED_ORIGINS` нет пути и завершающего `/`.

Без серверного API эта версия не откроет закрытые функции. Загружать весь исходный проект как статическую папку GitHub Pages нельзя: это не запускает Node.js и раскрывает серверные исходники. Для приватных материалов рекомендуется приватный репозиторий.

## Можно ли обновлять после запуска

Да. Обновляйте код в том же репозитории и развёртывайте новую версию. При включённом Auto Deploy Render может делать это после коммита. Сохраните те же `MONGODB_URI`, `MONGODB_DB` и другие приватные настройки. Обычное обновление кода не удаляет пользователей и покупки.

Эта версия не очищает коллекции при запуске и использует атомарные изменения отдельного документа для оплаты и состояния попытки. Для будущих изменений структуры предусмотрите миграции и резервные копии. Не удаляйте базу и не заменяйте её пустой.

## Перенос из прежней SQLite-версии

Перед обновлением сделайте резервную копию прежней базы. При запуске v2 на том же файле SQLite автоматически копируются аккаунты, сессии и отметки прочитанных уроков. Исходные SQL-таблицы остаются в базе; авторские вопросы из кода удалены. Старые авторские попытки и неподтверждённая история внешнего тренажёра не выдаются за новые проверенные результаты и не включаются в новую статистику.

Перенос подготовленных v2-записей в MongoDB:

```bash
node --env-file-if-exists=.env scripts/migrate-to-mongo.mjs /путь/к/старой/sat.sqlite
```

В `.env` должна быть строка целевой MongoDB. Скрипт не удаляет исходный файл, не перезаписывает конфликтующие записи и может продолжить незавершённое копирование. Сначала выполняйте перенос на копии базы и сохраняйте оригинал. Автоматический перенос всех прежних авторских попыток в новую схему не реализован.

## Проверки и ограничения

```bash
npm test
```

Проверяется полный серверный цикл, права на контент и заказы, оплата, отмена, повторные уведомления, истечение подписки, сохранение и повторение. Подробности фактических проверок — в `VALIDATION.md`.

- Сейчас шесть готовых уроков, а не полный SAT-курс.
- Внешние вопросы и исходные разборы на английском; уроки на трёх языках.
- Нет отправки email, подтверждения почты и восстановления забытого пароля. Эти функции нужно добавить для самостоятельного восстановления аккаунта перед широким платным запуском.
- Живые платежи и реальная MongoDB требуют вашей настройки.
- Доступность внешнего банка не гарантирована.
- Для больших нагрузок, резервного копирования, почты и мониторинга нужны отдельные настройки и проверка нагрузки.

## Состав проекта

- `public/` — публичные страницы, интерфейс и стили; платных ключей и полных уроков здесь нет.
- `server/content.mjs` — шесть трёхъязычных уроков.
- `server/questions.mjs` — загрузка и нормализация внешних заданий; не выдаёт ключи во время теста.
- `server/private/official-variants.json` — прежние подборки ID внешних вопросов, не тексты авторского банка.
- `server/exams.mjs` — состояние попытки, таймеры, проверка и запись результатов.
- `server/store.mjs` — MongoDB / SQLite, индексы и атомарные изменения.
- `server/billing.mjs` — тариф, заказы, подписка, Payme и локальная демонстрация.
- `scripts/admin.mjs` — просмотр заказов/жалоб, подтверждение ручной оплаты только владельцем сервера.
- `tests/` — изолированные проверки. Искусственные задания существуют только во временных тестовых файлах и не являются материалом сайта.
